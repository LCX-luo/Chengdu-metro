

# 成都地铁乘车足迹可视化探索图 (Chengdu Metro Footprint)

本项目是一个基于纯前端（HTML + JavaScript + ECharts）的成都地铁乘车记录热力图与可视化数据看板。
现在以 `index.html` 为统一入口：一次导入 CSV，通过顶部导航切换地图看板、时间分析和探索洞察。时间分析的日期、站点、星期与去重筛选同步到地图；数据只保留在当前浏览器页面内存中。旧 `final_map.html` 地址自动转入统一入口。
通过导入个人的乘车记录 CSV 文件，程序能够自动分析进出站频次，并在基于真实地理坐标（WGS-84）的成都地铁线网上，点亮你涉足过的每一个车站。
“隐私安全承诺：本工具完全基于纯前端浏览器本地计算，您选择的 CSV 行程文件仅在您自己的设备内存中进行解析，绝不会上传到任何云端服务器，请放心使用。”
## ✨ 核心功能

* **🔒 数据纯本地处理**：彻底的数据解耦，乘车记录（CSV）仅在浏览器内存中解析，无需上传任何服务器，保护个人隐私。
* **🗺️ 双视图自由切换**：
    * **地理坐标地图**：基于真实的经纬度渲染全网地铁站与轨道连线，高频站点呈现从翠绿到深红的平滑色彩渐变，未涉足站点自动缩放为微小黑点（视觉降噪）。
    * **数据排行统计图**：自动生成柱状图统计，并配备底部横向滚动条（DataZoom），适配海量站点流畅展示。
* **🎯 极高精度与防错机制**：
    * 采用纯正的 `WGS-84` 国际标准坐标，彻底消除国内商业地图 API 常见的“火星坐标系偏移”。
    * 内置“截断白名单”与“别名同义词库 (Alias Map)”，配合**严格匹配（Fail-Fast）算法**，彻底杜绝模糊匹配导致的“幽灵站点”Bug。

## 🚀 快速启动与使用方法

由于现代浏览器极其严格的跨域和沙盒安全策略，网页在尝试读取同目录下的 `.geojson` 数据时，如果直接双击打开 `.html`（即 `file:///` 协议），会被浏览器强制拦截。因此，**必须使用本地服务器环境运行。**

### 运行步骤：

1. **确保已安装 Python**（Windows/Mac 均适用）。
2. 打开终端（Terminal / PowerShell），使用 `cd` 命令进入到当前项目目录，例如：
```bash
cd C:\Users\10109\Desktop\metro

```


3. 启动一个轻量的本地 HTTP 服务器：
```bash
python -m http.server 8000 --bind 127.0.0.1

```


4. 打开浏览器，访问以下地址：
[http://127.0.0.1:8000/final_map.html](http://127.0.0.1:8000/final_map.html)
5. 在页面左侧控制面板，点击 **“选择文件”**，选择自己的行程 CSV。
6. 享受你的地铁足迹探索！

## 📄 数据准备 (CSV 格式说明)

### 一键启动与时间分析

Windows 双击 `start_dashboards.bat`：自动在脚本目录启动服务器，并打开综合看板 `index.html`。优先使用端口 8000；端口占用时尝试 8001–8010，实际地址显示在窗口中。保持窗口开启，关闭窗口或按 Ctrl+C 停止服务器。需要已安装 Python 3。

手动启动服务器后，访问 [http://127.0.0.1:8000/index.html](http://127.0.0.1:8000/index.html)，在“导入数据”中选择 CSV（支持多选合并），随后切换三个分析视图，无需再次导入。默认按出发站、到达站、完整时间去重。`time_analysis.html` 仍可单独使用，但独立标签页不共享内存；推荐使用综合入口。

探索洞察包括：站点首次出现进度、路线次数与集中度、相邻交易时间间隔、各年月份对比、月度活跃画像、双向路线对比、站点 × 小时热力图和高频日期提示。所有口径均依据当前筛选记录，不推断真实首次到访、同日往返或乘车时长。统计导出同时包含探索概览、月度画像和双向路线等内容。

有轨电车记录的出发站与到达站统一为“有轨电车”，每行计一笔行程；地图和站点端点热力图分别累加出发、到达，因此一笔有轨电车贡献两次站点频次。未匹配到底图的站名仍保留在行程分析中，并在地图摘要中提示。

时间分析功能：

- 日期范围、站点关键词、周一至周五 / 周末筛选，以及重复行保留开关。
- 年、季度、月、ISO 周、日统计；缺失日期补零，上一期环比。
- 24 小时分布、每星期分布、星期 × 小时热力图、每日活跃日历。
- 每日次数、7 日移动均值、累计次数、每日次数分布。
- 自定义早晚高峰（含跨午夜）与高峰占比，重叠时段不重复计数。
- 日均、活跃日均、最长连续活跃 / 空白天数、最繁忙日期和小时、最早 / 最晚 / 中位时刻。
- 出发站、到达站 Top 15、全部有向路线排行、行程预览。
- 导出统计 CSV、导出筛选行程 CSV、浏览器打印 / 保存 PDF。
- 非法日期与重复记录检查；图表 CDN 不可用时仍可查看统计表和导出。

统计按行程单交易时间归组，不代表实际进站时刻或乘车时长。周一至周五没有扣除节假日，也未加入调休；日均分母为筛选范围的日历天数。首末期可能不完整，环比需结合覆盖范围理解。所有行程数据在浏览器内存中处理，刷新后清空；图表 CDN 需要联网。

分析交互参考 [Power BI 日期层级](https://learn.microsoft.com/en-us/power-bi/create-reports/desktop-inline-hierarchy-labels)；图表缩放参考 [ECharts 时间轴](https://echarts.apache.org/handbook/en/concepts/axis/)。

`.gitignore` 忽略个人 CSV、PDF、临时导出和本地环境，只保留 `test.csv` 演示数据。请将个人行程文件保留在本机。

为了让解析器正常工作，你上传的 CSV 文件必须包含合法的表头。程序主要读取 `出发站` 和 `到达站` 两列。

**标准 CSV 格式示例：**

```csv
序号,出发站,到达站,时间
1,春熙路,建设北路,2026.04.22 18:25
2,省体育馆,前锋路,2026.04.19 16:19
3,天府广场,成都西站,2026.01.24 17:38

```

## 🛠️ 常见问题与排查指南 (FAQ)

### 1. 页面无法渲染 / 提示“基础数据拉取故障”

* **原因**：大概率是直接双击打开了 HTML 文件，或者浏览器拦截了数据请求。
* **排查**：按下 `F12` 打开控制台 (Console)，如果看到 `CORS policy` 或 `file:///` 相关的红色报错，请严格按照**使用方法**中的 `python -m http.server` 步骤启动。

### 2. CSV 解析成功，但某些我去过的站没有被统计（匹配失败）

由于开源底图的命名习惯可能与你的账单记录存在差异（例如错别字，或名称被官方修改），程序采用了严格匹配策略，匹配不上的会直接丢弃。

* **排查方法**：
1. 导入 CSV 后，按下 `F12` 打开浏览器开发者工具。
2. 切换到 **控制台 (Console)**。
3. 寻找黄色的警告信息：`【警告】以下您的 CSV 行程站点无法在底图中匹配，已被舍弃。请在 stationAliasMap 中配置对应关系：["某某站", "某某站"]`


* **修复方法**：
打开 `index.html`，搜索 `const stationAliasMap = { ... }`。
将报错的站名映射为地图底图中的正确名字。例如，如果你的账单叫“界碑”，底图叫“界牌”，只需增加一行：
```javascript
const stationAliasMap = {
    // "你的CSV站名": "底图正确站名"
    "界碑": "界牌"
};

```



### 3. CSV 无法读取 / 提示“CSV结构无法解析”

* **原因**：CSV 文件使用了不支持的编码，或者数据列被损坏。
* **排查**：请确保 CSV 文件使用 `UTF-8` 编码保存。你可以用记事本打开 CSV，选择“另存为”，在编码选项中选择 `UTF-8`。同时确认文件包含正确的逗号分隔符 `,`。
