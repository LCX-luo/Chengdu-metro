# 成都地铁行程导入与综合分析指南

1. 在成都地铁 App 的“我的 → 我的行程”中按当前 App 流程导出行程单。如果通过开发票流程接收文件，请核对所选行程和邮箱，按实际报销要求操作。
2. 开发票邮件可能包含发票 PDF、XML、OFD 等多个附件；下载其中的“行程单.pdf”即可。然后打开网站的“导入数据”，点击“选择 PDF 行程单”，可一次选择多份。无需先截图或转换 CSV。
3. 网页在浏览器本地提取文字并核对每份账单笔数、金额。全部成功后进入地图；失败时显示简短原因，F12 → Console 的 `[行程导入]` 日志可诊断，旧数据保留。
4. 支持成都地铁文字型行程单，扫描件和加密文件暂不支持；加密文件需先解锁。
5. 也可选择 CSV。所需表头为 `出发站,到达站,时间`；时间包含年月日、小时和分钟，可保留秒。可选金额列为 `金额` 或 `金额(元)`，单位元，最多两位小数。
6. 一次导入后，顶部切换地图看板、时间分析、探索洞察、花费分析。旧版 CSV 缺少金额时，花费页会提示，其他分析正常使用。
7. 在分析页修改日期、每天的几点几分、站点、星期或高峰参数后，点击“确认筛选”才同步生效；未改动时按钮灰色。每天开始包含、结束不包含，支持跨午夜，留空表示不限。重置立即恢复完整范围。
8. 花费分析只汇总已知合法金额，缺失值不当成 0 元；每笔有轨电车只计一笔费用。地图的出发、到达端点各计一次站点频次。
9. 分析页底部可导出统计 CSV、带金额的筛选行程 CSV，也可打印 / 保存 PDF。个人文件不上传，刷新后需重新导入。
10. 本地使用时双击 `start_dashboards.bat`；也可在目录运行 `python -m http.server 8000 --bind 127.0.0.1`，访问 `http://127.0.0.1:8000/index.html`。

## 可选：AI 提取 CSV 提示词

网页支持直接导入行程单 PDF。需要转换为 CSV 时，将原始行程单 PDF 上传给支持读取文件的 AI，并使用下方提示词。核对结果后在网页选择 CSV 导入；新格式保留费用，旧版无金额 CSV 仍可导入，但无法提供完整花费分析。

```text
请根据我上传的成都地铁行程单 PDF，生成可直接导入成都地铁行程分析网页的 CSV 文件。

1. 逐页提取所有行程明细，包括多份 PDF、同一 PDF 内的多个账单段，以及跨页续接的行程；不要把发票或账单合计当成行程。
2. 固定五列表头：序号,出发站,到达站,时间,金额。
3. 时间格式为 YYYY.MM.DD HH:mm:ss，保留原始秒数；原文只有分钟时使用 YYYY.MM.DD HH:mm，不编造秒数。
4. 金额填写该笔行程的实际费用，单位元，保留两位小数，不附加货币符号。真实 0 元填 0.00；确实缺失的金额留空并说明，不能填 0 或按票价推算。
5. 有轨电车每条明细只生成一行，出发站、到达站均填写“有轨电车”，该笔费用只保留一次。行程单中有轨电车对应的“--”或“00”等占位站名也按此处理；其他无法识别的站名不要擅自归为有轨电车。
6. 保留正式站名，修正 PDF 字形兼容字符，例如“⻰”转为“龙”、“⻋”转为“车”，不要猜测或随意更名。
7. 先核对每个账单段的明细笔数与金额合计是否与原文一致，再合并。仅当出发站、到达站、完整时间和金额均相同时去重；同一站点及完整时间出现不同金额时，请单独报告冲突，不擅自选一个。
8. 按时间升序排列，序号从 1 连续编号。输出 UTF-8（建议带 BOM）编码的 CSV 下载文件；字段有逗号、引号或换行时按标准 CSV 转义。
9. 另外简要报告来源文件、原始笔数、去重后笔数、已知费用总额、有轨电车笔数，以及缺失金额或冲突。如果无法完整识别或核对不一致，请指出具体文件、页码和原因，不编造数据。

CSV 格式示例（金额仅用于展示格式）：
序号,出发站,到达站,时间,金额
1,犀浦,洪河,2026.10.01 12:15:19,5.00
2,有轨电车,有轨电车,2026.10.05 21:07:40,1.60
```
